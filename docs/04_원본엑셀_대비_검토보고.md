## 2. 상세 진단과 보강안

### 🔴 치명 — 개강 전 반드시 수정

| # | 문제 (Fact) | 영향 (So What) | 보강안 |
|:-:|---|---|---|
| R1 | **예산 수입/지출 미구분.** 원본은 '교회예산·회비' = 수입, 나머지 8개 = 지출로 2열 관리. 앱은 10개를 한 열(예산)로 합산 | 합계에 수입과 지출 예산이 섞여 **집행률·잔액이 틀리게** 표시됨 | 항목별 '구분(수입/지출)' 지정 → **수입 합계 · 지출 합계 · 잔액** 3개 수치로 표시. 회비 수입 = 납부 인원 × 회비 자동 계산(R4 연동) |
| R2 | **집결시간 불일치.** 원본 큐시트는 14:30 교육준비 시작. 앱 Run-of-Show도 14:30이지만, D-Day 체크(T-120=13:30)와 Staff D-1 안내 문구는 **"집결 13:30"** | 운영진 단톡방에 **잘못된 집결시간(13:30)이 발송**될 수 있음 | 설정에 **'집결시간'(기본 14:30)** 추가 → D-Day 체크 시각·Staff 안내 문구·Run-of-Show가 한 값에서 자동 계산 |
| R3 | **원본 파일에 민감정보 포함:** 외부 시스템 관리자 아이디·비밀번호, 회비 입금 계좌·예금주, 운영진 휴대폰 번호 | 파일이 공유되면 계정 탈취·개인정보 노출 | 앱·저장소에는 **넣지 않는 원칙 유지**(현 설계 그대로). **사용자 조치:** 해당 비밀번호 변경, 원본 파일은 공유 드라이브·단톡방에 올리지 않기 |

### 🟠 높음 — 원본 업무 누락 (개강 전)

| # | 원본에 있는 것 | 앱 현황 | 보강안 |
|:-:|---|---|---|
| H1 | **회비 관리:** 명단 '회비납부' 열, 준비 '회비 결정(4 또는 5만원)', 개강안내 '회비' | 회비 개념 없음 | 교육생별 **'회비 납부' 체크** + 설정 **'회비 금액'** → 운영 현황에 **납부율 KPI**, 예산 회비 수입 자동 반영. 입금 계좌는 시트 설정에만 저장 |
| H2 | **준비 체크 2개:** '회비 결정', '과제 확인' + 항목별 비고(인쇄소, 비품 수령처 등) | 9개만 있음, 비고 칸 없음 | 체크리스트 **11개로 확장**, 항목별 **메모 칸** 추가 |
| H3 | **휴강 주:** 전년도 일정에 1주 휴강(명절)이 있었고 개강안내에 휴강일 명시 | '개강일 기준 재계산'은 무조건 매주 7일 간격 → 휴강 반영 불가(수동 수정해도 재계산 시 덮어씀) | 설정에 **'휴강일'** 추가 → 이후 주차 날짜가 **자동으로 1주씩 밀림**, 개강 안내 문구에 휴강 표시 |

## 4. 실행 계획 반영 — '1.5단계 원본 보강' 신설

| 단계 | 기간 | 내용 | 변경 범위 |
|---|---|---|---|
| 1 | 완료 | 앱 골격·원본 화면 이식 | – |
| **1.5 (신설)** | **1일** | 🔴 R1·R2 + 🟠 H1~H4 보강 | 화면(index.html) + 서버(Code.gs). 시트는 **열을 끝에 추가**하는 방식 → 기존 데이터 그대로 사용 |
| 2 | 1~2일 | 통신 어댑터 (구글 시트 연결) | 계획 그대로 |
| 3~7 | – | 앱화 → QA → UAT → 실운영 → 개강 | 계획 그대로 |
| 개강 후 | 1~2주 | 🟡 M1~M4 | 운영하면서 보강 |

> **설계 원칙 유지** — 보강도 '원본 재사용 + 최소 변경' 원칙을 지킵니다. 기존 시트 17개 구조는 바꾸지 않고, 필요한 칸만 **맨 끝에 추가**하므로 이미 입력된 데이터는 영향을 받지 않습니다.
